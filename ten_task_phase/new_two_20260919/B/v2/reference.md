## Complete per-candidate judgment
7138 -> original RFC7231 §5.3.2. NO: the older Accept header includes text/html;q=0.7, so text/html;level=3 gets 0.7 by specificity. RFC9110 changed the more-specific branch to text/plain; the residual text/html;level=3 should receive text/*'s 0.3. Copying the new 0.3 correction into the old table would introduce an error. The erratum itself explicitly mentions that the old example is correct; this is a legitimate partial shortcut.

7306 -> original RFC7233 §2.1. YES: byte-ranges-specifier = bytes-unit "=" byte-range-set lacks whitespace after the equals. RFC7233 §1.2 imports the list extension from RFC7230 §7. The recipient expansion starts *( "," OWS ) element, so optional whitespace following a comma does not permit an initial standalone space. The report's witness bytes= 0-999, 4500-5499, -1000 is rejected by the old grammar and accepted with the reported OWS insertion. RFC7233 Appendix D independently shows this expansion; it is corroboration rather than the primary requested section. The main corresponding byte-range definition is §2.1, not the Range header's §3.1 or imported list §7. This task asks a technical defect comparison per erratum, not every place one might edit a grammar or proof of a separately verified legacy erratum.

7419 -> original RFC7231 §3.1.1.2. NO: the added RFC9110 sentence wrongly names Accept-Encoding in a charset discussion. The corresponding older concept is Charset §3.1.1.2; it lacks that erroneous sentence. Its supporting Accept-Charset definition (§5.3.3) uses charset, while Accept-Encoding (§5.3.4) uses codings and §3.1.2.1 relates content-codings to Accept-Encoding. Absence of the new sentence is not absence of the concept, and the older definitions already distinguish the two.

## Dependency, counterexamples and shortcuts
Erratum identity determines the legacy concept/example. Its own context determines which supporting definition is needed. In the grammar branch, the predecessor's syntax declaration points to a different RFC's list rule; interpreting just the visually similar production with an assumed implied-whitespace convention gives the wrong result. In the Accept branch, reusing a modern example's header changes the old table's expected result. In the charset branch, equating content codings and character sets makes a false backport recommendation.

All legal direct search, parallel page reads, erratum notes, collected grammar and prior standards knowledge are allowed. A one-page errata summary gives 7138's legacy answer but does not resolve all legacy section locations, the imported 2014 grammar, or the old charset definitions. No fixed request depth or forced serial tool order is claimed. The question is worth testing for semantic-version confusion, not certified difficult before a blind result. It may prove easy.
