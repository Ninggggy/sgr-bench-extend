## 容易混淆的协议边界

- A v1 打开了包括 146 页评估和 284 页决议汇编在内的单篇原始 PDF。登记协议允许单篇原始文件；没有调用数据库导出或批量下载接口。搜索返回中出现带 maxrows=200 的无关链接，模型没有打开这些链接，不能把搜索结果中的链接当作实际分页请求。
- A v2 CG 的 27 个名字查找是在同一篇已定位的 IBDB 制作记录内执行 find，不是抓取 27 个个人记录；GO 同样使用原始制作记录及页内查找。两份原始演员表没有预先给出跨制作的交集及分类答案。
- A v3 读取指定版本的 europe 原始文本和国家索引，GO 还跨公开镜像确认。这是单篇源文件和身份索引，没有下载完整发布归档，没有使用数据 API、编译器或预先计算好的逆映射答案。
- B v2 CG 读取 greenbytes 的 HTTP 勘误状态索引。实际内容为勘误编号、所属 RFC、日期、状态、提交者及问题链接，没有给出题目所需的旧版适用性判断；因此属于允许的目录元数据，不是预合并必要答案。官方 errata_search.php 重定向后的页面是正常 HTML 检索页，不因地址带参数就成为数据 API。没有自设超限分页。
- B v2 CG 的失败地址没有通过其他传输工具绕过；模型使用普通搜索和可读官方页面补齐。访问错误被保留，没有补零、重抽，也没有据其申报低分成功。

## 限定

这是基于已保存输入、隔离及完整可见工具轨迹的主控复核，不是新增的一次独立 Astra 审查，也不声称能够证明服务端不可见的内部行为。verification.json 中 pending_trace_review 是运行器配置检查阶段的状态，最终取证结论另存于 retrieval_review.json，不能只凭 verification 的 passed 判断轨迹合规。

本复核不改变原结论：A 的六次有效成绩全部 100%；B 的两次原始成绩不能用于能力验收；两题目标未完成。
