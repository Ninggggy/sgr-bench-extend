## 严格 SGR 与题面要求

具体拟议依赖是：从协议注册范围发现 deprecated 的数值身份及规范引用 → 识别该规范对应的草稿族 → 在官方规范记录选择该族的 History 视图 → 取得默认规范正文没有的历史计划日期、受审版本和计划值。网站 W 在这个关键阶段是 Datatracker；IANA 注册范围是前序发现来源。记录参数来自前一步，而 History 是实际可观察的视图选择（HTML 736–764 行导航）。普通引用跳转本身不证明 SGR；这里的支持点是选择正确 family 的 History 状态才暴露历史提案。发现 family 后一次取得完整 History 是允许的结果驱动批量取证，并不自动取消该依赖。

真实边界：没有要求第二层回查或永久 HTTP 重放。旧 r03 固定的 registry + RFC 材料能覆盖登记及替代关系，不能直接覆盖本次历史审查日期/计划；新保存的 History 当然足够本地重算，这是研究参考的输入，并非证明求解者预先得到固定全材料。另一方面，只有一个 family 和一条短提案，可能仍很容易；通用搜索也可能直接找到这条审查。未做独立路径核验或模型测试，不能声称排除所有直接命中或固定材料捷径，更不能宣布低于 70%。机制判断为“存在具体状态依赖见证，严格准入尚待独立语义审查”，不是已通过。

论文 `chinese_1st_ver/latex/sections/3_Method.tex:12` 明确要求 q 不揭示目标网站。上一草稿写 IANA Functions Operator，是合法的审查角色名，但若将整个多站点生态称 W，它也明显提示其中一个站点；此外 CG 写 History 直接提示视图。不能因为没有 URL 就自动判合格，也不能通过改成谜语掩盖来源。

本目录 `paired_draft.json` 提供自然领域表述：保留 16 位 TLS ExtensionType、DTLS-only、deprecated 的完整范围，使用“负责该登记的主管方自己的实质审查”而非机构品牌，排除 shepherd、其他评议及状态记录。它没有预给 website、family、revision、日期或旧值；范围没有因隐藏品牌而缩减。这个角色在本证据中明确对应 IANA Functions Operator，并非模糊放宽到任意评论。CG 仅提供发现后选择文档历史视图的过程指导；GO 保留同一结果条件。此候选表述仍是待审查稿，不能以改了几个名字就认定 Method:12 合格。独立审查需确定：协议范围是否自然、角色定义是否精确、两条件是否仍要求识别目标网站，以及发现来源到官方历史视图的依赖是否确实必要。
