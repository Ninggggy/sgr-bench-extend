## 3. 构造、参考与难度验证流程

每题按同一流程推进，复用已成立的证据，避免重复验证。

1. **整理旧版实际成功路径。**\
   区分内容错误、合法捷径、访问失败及评分问题。列出旧题为什么容易，以及此次新证据要改变哪个必要判断。没有实质变化依据的旧版不重新测试。

2. **先验证关键来源，再扩展完整范围。**\
   构造端允许批量导出，访问与公开路径验证按现有浏览器插件要求执行。确认候选全集、逐项纳排和关键历史版本后，保存来源及获取日期。取消请求上限不等于无限搜索：具体线索被反驳或查尽后，改变方向或停止。

3. **分别验证两种求解路径。**\
   构造侧实际走通浏览器可复现路径；另外确认盲测使用普通网页搜索和 webfetch 也能取得必要证据。浏览器能显示的动态内容不能自动视为 webfetch 可得。盲测不要求浏览器插件。

4. **重建可重算参考。**\
   程序从原始字段生成答案，同时输出候选、纳排理由和字段证据；处理并列、缺失、复合标识及版本漂移。历史截止时间与实际访问日期分开记录。完整性或唯一性未成立时，产物保持草稿状态。

5. **检查难点是否真实、捷径是否有效。**\
   对每个拟新增判断，用原始材料验证：若跳过这一步，具体会漏掉什么、纳入什么或选错哪个版本。再检查单篇论文、普通汇总页、统一类别、当前版本替代历史版本等合法简化路径。不能仅用“跨多个网站”或“字段很多”证明难度。

6. **完成配对题面、审查和评分适配。**\
   CG／GO 必要条件一致，表达通俗，不泄露正确身份或私有候选。按具体问题修正，可多轮审查，总审查预算不变。测试前检查正常 Markdown 表格、并列答案、别名、复合标识、缺失值及重复行；不在看到成绩后更改正式评分规则。

优先为六题各预留一次内容审查和一对盲测，即 **6 次审查、12 次盲测**。剩余 **5 次审查、14 次盲测**用于有证据支持的后续实质版本；不能让一题提前用尽其他题的首对额度。某题确定停止后，其未用额度回到共享余额，不扩大任何题的版本上限。

## 4. 盲测、判定与下一版本

测试前登记最终 CG／GO、参考、重算程序、评分规则、模型、工具协议及两个试次。登记与执行使用同一版本，两个试次均执行，不因第一面高分取消第二面。

盲测环境只提供题面、公共协议和允许工具：

- 允许普通网页搜索、webfetch、正常分页、单条记录和单篇原文。
- 禁止大规模 fetch、完整实质候选数据的批量下载、预合并答案获取、拆分实现批量抓取，以及直接数据接口。
- 沿用现有分页规定；不恢复 60 请求或外部并发 2 项限制。
- 不提供构造缓存、参考答案、历史轨迹、既有成绩或其他试次内容。

测后独立检查原始轨迹，核对实际请求、接口调用、批量获取、答案暴露和环境问题。配置检查通过不等于获取合规。

| 结果                   | 处理                               |
| -------------------- | -------------------------------- |
| 质量通过，两面有效且分别严格低于 70% | 该题达标，停止修改和测试                     |
| 任一面达到或超过 70%         | 保留成绩，分析实际成功路径；只有新证据支持实质变化才进入下一版本 |
| 访问、解析、评分或答案暴露造成混淆    | 不据此达标，不补零、不重抽；诊断原因并保留原试次         |
| 无新证据、单题版本用尽          | 停止该题，继续其他题；整轮仍未完成                |
| 累计预算用尽或没有可行方向        | 停止整轮，明确目标未完成                     |

若 Item-F1 为精确比例 `n/d`，使用 **`10n < 7d`** 判断，CG、GO 分开验收。Row-F1、整题全对及内容错误类型同时报告，但不替代 Item-F1 条件。

本轮成绩属于开发筛选后的单次测试，不宣称无偏最终评估，也不等同于历史正式收录的三次均值。
