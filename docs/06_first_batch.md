# 首批构造安排

2026-09-09更新：本页为WQP闭环之前的安排。旧题运行、WQP r03与Sol复测已完成，后续首轮改按[扩展计划](08_scale_plan.md)的5生态8候选执行准备；以下四生态名额与未完成状态保留为历史设计。

## 目标与范围

先探索8个底题候选，覆盖WQP、Water Office、CFPB complaints、ChemExpo各2个；若全部成立最多产生16条CG/GO。8是资源规划，不是承诺接收数量。完整扩展仍限定于现有50题的12生态。

首批使用4生态，是因为已有题提供了清楚的升级参照；它不能代表完整12生态均已更难。只有扩展到可比来源构成并完成确认测试后，才讨论整个新集相对旧50题的难度。

## 第一个闭环优先做WQP

本轮已实际取得TCEQMAIN-10598站点CSV，并进一步取得TCEQMAIN-10580在1978年的18条活动与290条结果。四种指标在站点全年均出现，但并非每个有结果的活动都同时具有四者。这给出了活动粒度方向的真实观察；响应中的介质全部写Other。补充检查发现温度有12条deg C与10条deg F，同活动还存在同单位电导率/pH多值，且当前响应没有ResultIdentifier。因此尚无每活动唯一数值oracle，不能自行择首或平均。详见[探测记录](../research/README.md)、[原始响应](../research/wqp_result_1978_probe.response)及[机制与限制](04_sites.md)。

1. 以旧waterquality_004/005为参照，查清组织内Activity身份、介质、深度及结果限定符。Activity不等于完整站点访问，跨活动面板必须有官方关联依据。[EPA概念定义](https://www.epa.gov/waterdata/concepts-and-definitions-storage-and-retrieval-and-water-quality-exchange)
2. 先取一个有界时间切片的Activity和Result，核对实际profile、官方身份键与同活动多值原因。数值题须有明确结果身份和多值处理依据；没有可靠身份就终止该方向。
3. 寻找“各组分别存在、同次活动不完整”的真实反例；再扩大到有限候选站全集。
4. 由自然监测需求确定面板规则，而不是挑出刚好使某站胜出的条件。
5. 从证据生成oracle及CG/GO，独立求解、API批量攻击、证据审计。
6. 相同配置重跑旧近邻，确认新题难点确实来自状态和身份依赖；若只剩简单下载后计算，记录为不满足升级目标。

以上是探索任务，不是可发布题干。构造者可基于实地发现替换机会；替换理由、证据与旧题差异都要记录。其他生态的方向见[网站文档](04_sites.md)。

Water Office先做合法批量路径挑战：多站日均服务和HYDAT可能预先覆盖整个有限季节，窗口尚未确定并不阻止取数。只有实际路径仍支持所声称的状态与资格依赖，才继续设计；不能把本地计算出的窗口自动算成多轮检索难度。下载当前数据库与完整候选求解尚未执行，见[站点复核](../research/site_review_2026-09-08.md)。

ChemExpo-B依据已核实的筛选语义替换旧假设：General筛选不包含已细分产品，页面仅展示产品置信度最高的PUC归属；不能声称已发现同产品全部多类别。Chemicals表的文档出现次数也不能当产品数。实际产品枚举与赢家翻转仍待探索。[化学物检索指南](https://comptox.epa.gov/chemexpo/static/user_guide/explore_chemicals.html)、[产品与PUC指南](https://comptox.epa.gov/chemexpo/static/user_guide/explore_products.html)

## 第一个候选的可验收结果

- 明确的研究目标、有限候选范围、共同纳排/排序定义。
- 实际源数据、完整枚举依据、纳排账本、每个输出字段的证据与可运行参考解。
- CG/GO一对，必要语义逐项对齐，互用同一oracle。
- CG和GO各有两份独立盲解，共4次；冲突追加复查，不能由作者解释后直接算盲解成功。
- CG和GO各有一次不知道gold的捷径尝试，共2次，以及可看到全证据的审计裁决。
- 同模型、同工具、同预算的旧题对照与独立确认轮，结果只支持到哪一步就标到哪一步。

## 实现顺序

**已完成**：设计文档、11份阶段prompt、结构化结果schema、离线准备工具、正式旧题清单与少量接口探测。

**实现里程碑一**：建立有实际读隔离的Codex工作进程；确认检索工具能用，先用旧题跑通输入→结果→评分→事件记录。这里检查的是运行链路，不能把一次旧题得分当旧集难度。

**实现里程碑二**：针对第一个WQP候选写提取与参考计算代码，走完内容验证；只有真实数据支持时才推进。

**实现里程碑三**：加入阶段队列、错误分类、预算和恢复；再展开8个名额与配对难度试验。

**实现里程碑四**：据试验结果扩展其余生态、完成整体难度对照，整理正式数据与论文方法更新。没有必要预先完成12套通用网页适配器。

## 示例资源配置的含义

[config.example.json](../config.example.json)建议pilot最多120次模型调用、最长24小时、单次6000秒、每候选最多2次修订。调用数包含失败与重试，重复求解会消耗多次调用。120次并不足以覆盖完整旧50题三次双题面对照；完整实验需要单独估算，不能通过漏测凑进预算。

120次也不能保证完成8个新底题。按4生态各探索一次、8题全部进入内容验证和确认的粗略下界：4次探索 + 8 × 11次内容链调用 + 48次新题确认 = 140次。每题11次包括design/reference/pair、4次盲解、2次攻击、audit/adjudicator；48次确认按8题 × CG/GO两变体 × 3次独立确认计。这里尚未包含旧题对照、难度筛选、修复、失败重试和controller。保留120为示例上限，不自动提高预算；范围须按实际剩余额度缩减，并明确未完成部分。

环境受额度限制时记录停止点。真实耗费取决于页面响应、工具可用性、参考解复杂度和修订率，本轮没有实测吞吐量或费用。
