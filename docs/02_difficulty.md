# 如何验证“比现有50底题更难”

2026-09-09更新：后续盲解、攻击、筛选与确认使用Sol/medium，构造与证据审计使用GPT-6/high。本文以下保留原GPT-6设计，统计原则继续适用；当前结果与对照污染处理见[扩展计划](08_scale_plan.md)及[复测复核](../research/sol_retest_review_2026-09-09.md)。

## 三个不同命题

1. **结构升级**：候选具有旧近邻没有的、能改变答案的依赖。可以在构造时证明一些具体差异，但不是整体难度结论。
2. **对照题更难**：同模型、同工具、同预算下，新底题比分配给它的旧底题更难。有限试次只能给出带不确定性的证据。
3. **新集合整体更难**：保持网站/来源组成可比后，新题集合的平均表现低于旧集合。这是默认研究目标。

“每个新题严格难于全部旧题，包括最难一题”不是能靠prompt保证的性质；若目标进一步收紧，应使用旧题最难分层作参照并增加测试，而不是默认成立。

## 结构检查

不设置一个武断的加权难度总分。对每个候选保留下列可解释描述及真实证据：

| 维度 | 记录方法 |
| --- | --- |
| 最长依赖链 | 只计后续操作必须读前步证据才能决定的节点；复制相同查询不重复加分 |
| 控制依赖 | 证据如何决定过滤参数、层级分支、时间窗口或回查范围 |
| 汇合与回查 | 哪些分支共用哪些身份键；后出现的证据怎样改变先前选择 |
| 同时保留的状态 | 实际不能混淆的范围/版本/群体/粒度，不以界面控件数替代 |
| 有效干扰候选 | 满足大部分条件但被某条真实证据排除的近邻，保存排除依据 |
| 完整性负担 | 需要证明的候选范围和分页/全量边界，不能只有赢家证据 |
| 压缩程度 | 中间候选量与最终输出量，辅助描述，不作为越大越好的目标 |

初步优先选择有至少一个新控制依赖和一个真实反例的候选。绝对链长、行数、字段数仅用于筛选资源规模，不据此判定比旧题难。输出规模尽量与近邻旧题接近，以减少纯枚举量与格式误差的混淆。

## 固定可比较的求解协议

本方案全程使用GPT-6，但区分用途：构造与证据核验可用较充分探索；难度求解用统一的受控配置。建议默认 `gpt-6-astra` / `high`，作为本方案起点，不声称是最优档位。若选max或其他档位，新旧题全部一致。不要用不同temperature制造所谓独立采样；GPT-6 Astra的相关参数支持以当前官方文档为准。

每次记录精确model/provider、Codex版本、effort、工具清单、提示版本、数据版本、执行日期、墙钟时间、实际工具事件及可得到的token用量。新旧题使用相同预算、缺失答案规则和中断语义。建议沿用旧稿6000秒上限/3000秒无进展阈值；也可先用较短预算做探索，但短预算结果不能与长预算结果混报。

受控工具优先沿用旧稿search/fetch/PDF；构造者若发现某题只有真实浏览器才能做，应转为单独的browser配置并把同类旧题一起重测，不能拿不可用工具制造困难。

## 筛选轮与确认轮分开

**便宜筛选**：每候选选1—3个近邻旧底题，以相同配置分别测试CG和GO。结果用于发现过易、无进展、访问失败和题面问题，允许据此修订。它是开发数据，不能当无偏的最终难度估计。

**确认轮**：候选内容和评分确定后，先在普通 `comparisons/analysis_plan.json` 中写明最终候选名单、旧题对照、来源权重、主指标、目标幅度、每题面试次数、停止与环境失败规则，再用新会话、新试次测试。计划是实验记录，不新增冻结机制。

换会话只解决上下文问题，不能消除反复选择的偏差。若根据确认结果删除容易题、挑出最难子集或继续修订，这轮就已用于开发。保留全部结果和选择历史；在下一次实验前确定最终集合，对整个集合做新的确认。不能只给修过的单题补一次运行，便继续把整体结果称为未参与选择的确认。预定轮次或资源耗尽仍不成立时，应报告未获支持；不能测试到第一次显著就结束。

建议初始3次完整尝试/题面；配置文件中的3次仅是小规模试运行值，不自动满足正式确认所需的精度。正式次数应根据开发轮波动、可接受误差和资源在观察确认结果前确定。0/3成功不等于不可解，1/3也不能证明某个概率阈值。需结合充分预算的独立参考求解和源证据证明可解。

对旧完整集合，50底题×2题面×3次=300次求解。若首批最终8个新底题，则8×2×3=48次新题求解，合计348次；这不包括构造和筛选成本，也不代表本轮已启动这些运行。正式批量规模取决于实际资源配置。

## 比较与统计

沿用论文Item-F1、Row-F1、P.O.A.，其中预先指定宏平均Item-F1为主要难度指标，另报整题完全正确率；答案解析失败单列。计算使用0—1量纲，展示为百分数时另行换算。先在每个题面内平均重复次数，再将CG与GO等权平均为底题得分，最后在底题/来源内汇总；不能因某题面有效运行更多就提高其权重。CG/GO及同题重复不是独立底题。

设每个新题对应一个预先选定旧近邻，定义差值为新题得分减旧题得分，负值表示新题更难。这是**匹配近邻分析**：以配对底题簇为重采样单位；若多个新题共用同一个旧题，必须整簇重采样，避免把同一对照复制成多份独立证据。

另做**相对原50题的集合分析**。设生态s有旧题n_s个，使用w_s=n_s/50的相同权重，计算Delta=sum_s w_s*(mean_new_s-mean_old_s)。首批仅四个生态时，只在这四个生态重归一化权重，并标为局部比较；不能外推到其余八个生态。旧题证据或配对无效导致部分题不可评分时，另列实际比较成员和分母，不把子集结果称为完整50题结果。

区分两种不确定性。默认主结论针对预先确定的这批新旧题：保持底题、题面及其权重不变，根据各题面重复运行估计模型作答波动；可在同一底题、同一题面内重采样独立运行，若按共同日期/工具批次成组执行，则按事先记录的批次相关结构处理。新旧任务之间没有天然的运行配对，不能只因replicate编号相同就配对。

另用按生态分层、以底题为簇的bootstrap描述结论对题目组成的敏感性；共享旧对照的匹配近邻分析须整簇处理，不能把复制的旧分数视为独立证据。该区间与固定题集的运行波动区间分开命名。当前新题经过目的性探索和筛选，底题bootstrap本身不能支持对所有未来SGR任务的总体推断。

集合层面至少报告：

- 原始新旧宏均值及差值、所有尝试的状态台账和端到端完成率。模型失败和部分答案按预定评分规则处理；真值无法确认的题不能凭空赋能力零分，环境失败的计入规则与可评分子集分母另列。
- 按相同生态权重计算的差值，避免仅因多造监管题而均值下降。
- Item-F1、Row-F1、整题正确率是否同向；P.O.A.只作补充，不能因少量共有行排序正确判轻松。
- 固定题集的运行波动区间、题目组成敏感性区间及各生态底题数/运行数；只有少数底题的生态不作精确排名。
- 与最近旧题、旧集较难分层的分别比较；筛选轮与确认轮分别列出。

### 可执行的判定提案

建议正式计划采用：**集合Delta点估计不高于-0.05，且预定的固定题集运行波动95%区间上界低于0**。这支持至少观察到5个百分点的差异，并支持平均差异为负；它不证明真实差异至少为5个百分点，后一个更强结论需区间上界也不高于-0.05。5个百分点是本方案的建议研究目标，不是原论文要求；可在确认运行前修改并记录理由。

同时检查Row-F1、整题正确率和CG/GO分项，避免一类变难掩盖另一类明显变容易。建议将“明确反向”定义为相应新减旧差值的预定95%区间下界高于0；出现时暂记inconclusive并调查，不能在看到结果后临时更换主指标。辅助指标的正点估计本身不等于已证实反向，仍须完整报告。

区间方法、重采样次数、生态权重、有效样本口径、相关运行的处理和辅助分析须在计划中指定。少数运行给出完全相同分数时，经验bootstrap的零宽区间不证明无随机性；样本少或旧题已处于零分附近时，bootstrap不能凭空增加信息。无法区分、原始方向不稳或存在无法解释的反向指标，写inconclusive。整题成功率只作辅助，不能用一个任务的多个字段冒充独立试次。

**单题confirmed_harder是另一结论。** 对照题、主要差值、试次数与判据也须预先规定；其不确定性来自独立运行而不是该题的行/字段数量。仅3次每题面的试运行默认保留screened或inconclusive，不据此发布精确单题难度结论。足够试次并满足预定判据，才填写该候选的confirmed_harder；若同时声称多道题分别显著更难，还需在计划中处理多重比较。

集合支持更难时，可以交付“内容已验证、集合层面更难”的题集，并保留各单题真实状态。不能把集合结果批量写成每个候选auto_validated。若目标明确要求每个题都已确认更难，则只有单题结论达到相应条件的候选可计入完成数量；数量不足就是未完成，不能更改标签补足。

旧题原始配对还存在genome_003/004交叉对应及部分语义差异，须依[配对记录](../research/old_pairing_exceptions.json)人工可审计地指定实际比较成员。无法唯一评分或复现的旧题单列，不静默修题或删除后仍声称完整50题可比；同时报告原50题端到端覆盖率及可比较子集。

## 防止“难但无效”

只因网络断开、登录/验证码、付费限制、文本截断、浏览器缺失或过大导出失败的候选，不记为有效困难题。环境失败独立标记，不在能力统计中静默删除：同时报告端到端完成率与可评测子集结果及分母。

如果重复求解始终完全没有有效进展，回到题面、官方可访问性和证据完整性检查；这与原文保留“部分但不完全进展”任务的构造意图一致。若提供正确候选集/状态说明的诊断尝试仍失败，可能主要是计算、解析或含糊规范问题，不能自动解释成SGR困难。

可增加一次明确标记的诊断：只提供正确入口，再提供关键状态说明，分别观察表现变化。诊断结果与正常盲测分开，不能用于主排名；这是定位困难来源的实验，不预设它一定能提升结果。

## 同模型构造的偏差

全GPT-6构造满足本次偏好，但筛选出的困难可能针对该系统特别强。新会话、差异化探索路径、确定性计算和同站对照可以降低泄露/误判，不能消除模型相关偏差。因此最终结论优先限定为“在所用GPT-6系统及协议下更难”；若以后要声称对所有agent普遍更难，再增加其他系统验证，不在本轮静默替换模型。
