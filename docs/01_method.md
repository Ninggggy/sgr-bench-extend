# 构造方法与循环

## 论文要求对应的可检查产物

| 要求 | 需要留下什么 | 不能用什么代替 |
| --- | --- | --- |
| 领域专属性 | 至少一个影响结果的领域定义，以及它所在的官方文档或记录 | 生僻名词堆砌 |
| 长尾来源 | 证据来自当前50底题已有生态；明确官方原文、参数查询或数据表 | 搜索摘要、模型知识 |
| 答案唯一可验证 | 有界候选集合、完整性说明、确定排序/并列/缺失规则、逐字段依据 | 两个模型碰巧给出同一答案 |
| 真值稳定 | 明确数据版本/历史区间和获取日期，保存支撑判断的原始材料 | 只写“历史数据”却不记录会变化的当前目录 |
| 防捷径 | 实际尝试搜索、直接详情页、官方API/批量下载等合法短路 | 硬性规定必须点击几次 |
| 逻辑依赖 | 中间证据怎样改变下步范围/参数/分支，及忽略此依赖的真实错误结果 | 独立查若干页面后简单拼表 |

全部数据仍取自真实来源。自动合成的是题目和查询工作流，不是数值、网页证据、作答轨迹或人工验证记录。正文题面默认英文，工作记录中文；CG/GO 的 schema、oracle、排序与纳排语义共用。中文翻译放在最终语义稳定之后，不引入第二套答案。

## 0. 旧题盘点

输入正式50个CG底题，并逐一解析匹配GO。只拿它们作为语义参照和难度对照，不把旧主表作当前GPT-6难度标尺。每题记录：生态、研究需求、候选集合、状态变量、数据/控制依赖、输出行列数、已知捷径、最强现有同类结构。

这一阶段不是重新设计整个旧基准。若某旧题当前不可访问或答案与证据失配，标记其不可用于当次对照，并报告对照覆盖；不悄悄换旧题或改oracle。本轮发现genome_003/004与同编号GO内容交叉对应，且维生素C题GO缺少部分CG明确条件；详见[对应记录](../research/old_pairing_exceptions.json)。对旧题配对须核对内容，不能只依赖编号或共享oracle。

## 1. 网站探索

探索者看到同生态旧题和历史证据，可用浏览器、搜索、官方文档、公开API以及本地代码。目标是建立小而具体的操作说明：实际有哪些控件/参数；一个参数改变后，哪些结果会改变；结果中哪些字段需要再决定下个查询；哪里会分页、跨版本、同名异物、默认过滤或含糊缺失。

每次只探测有界数据切片，逐步扩大范围。先理解公开的数据定义，再决定是否取数。遇到访问控制、登录、付费、持续错误或资源规模超限，记录不可用，不将其包装成题目难度。

输出 `site_profile.json` 和 `opportunities.json`。至少区分 `observed`（本次访问确认）、`documented`（仅文档描述）、`hypothesis`（待试验）。只允许前两类进入候选研究，未验证的机制不能支撑已完成题目。

## 2. 发现候选，而非先写漂亮题干

先提出一个自然研究需求及最多三种加强方式，在真实数据上尝试。保留能找到以下结构的候选：

- 多分支汇合后，还会反过来改变一个上游选择；执行图在展开回查轮次后应为有限有向无环图。
- 相同名称、不同标识/版本/粒度不能直接连接，官方映射能消除歧义。
- 详情页看似支持结论，但对完整候选范围、同批样本、有效窗口或最低证据要求进行核验后会推翻它。
- 某个缺失值有明确官方含义，不能等同于0；但不要求推断被来源隐去的私人统计数值。

候选必须列出1—3个最近旧题，说明差异。单纯改年份、换实体、增加字段或重复现有结构的轮次，不记为新结构。对声称增加难度的条件或关键依赖，要求忽略它的真实反事实能改变答案。定义问题所必需的范围、版本、单位或缺失规则即使本切片恰无反例也应保留，但不计为结构升级。

## 3. Oracle 与证据

参考解构造者必须先取证、再计算、后填写答案。保存：

- 枚举得到的候选全集或足以重建候选全集的官方导出、分页终止证据。
- 候选逐项去留及原因；不能只保留赢家的网页。
- 规范化后的中间表、稳定行键、原始字段到输出字段的映射。
- `solve_reference.py` 或 SQL：以保存的源数据为输入，通过可读计算得到 oracle；不能直接打印预写答案。
- 默认状态与目标状态的实际响应对照，标明证据何时出现、前步证据怎样决定后步参数；对合法批量路径另留实际尝试。
- 每个输出字段的来源定位，包含URL、取得时间、状态参数、页码/表号/行键；计算字段另列输入和计算式。
- 决定性条件的反事实重算：改用错误状态/忽略某个依赖时的真实结果，清楚标为核验产物，不作为任务真值。

按官方分页/总数/导出范围声明证据完整性。无法证明全量时，不把“目前找到的所有项”写成“所有符合项”。至少两个独立实现核对关键聚合或连接，例如原始行聚合与源站汇总，但先验证两者定义确实相同。

## 4. CG/GO 成对生成

从同一个规范化任务对象生成两个题面，输出规则只维护一份。建立谓词逐项对应表，标注CG中的每一项约束在GO中以何种语义存在。GO可隐去顺序与中间解法，不可隐去必要阈值、排除范围、时间定义、并列规则或数据含义。

避免嵌入答案ID、赢家名称、精确命中列表和可定位唯一答案的多余提示。领域上合理且确实需要的对象标识可以出现，但需在捷径测试中说明其没有消除核心检索问题。主评测不传 `start_url`；网站名称是否写进自然题面，应继承对应旧题口径，不能暗中改变source-discovery难度。

## 5. 每种题面两份盲解与一次盲攻击

验证者A、B各自只拿公开题面、schema、同一运行日期与允许工具。都不能看oracle、状态图、参考脚本、构造日志和对方输出；也不从构造对话fork。内容验证默认执行 A-CG、A-GO、B-CG、B-GO 四个全新会话，各不共享答案；这样每种题面均有两次独立求解。先做CG/GO各一次只算初筛，不能据此声称已取得每种题面的独立复核。

盲攻击者分别对CG和GO拿相同公开输入，专门寻找合法最短解法：直接搜索、详情页、全文表、API、批量导出、已发布基准泄露。它看不到gold，以避免使用答案反向查找制造不现实捷径。之后证据审计者可看全材料，按答案比较判断攻击是否成功，并检查状态需求有没有被消除。

上下文隔离不等于统计独立，也不等于文件读取隔离。生产实现需要实际限制私有材料的可读范围，详见运行文档。

## 6. 归因与修订

输出四类结论：`revise`、`reject`、`ready_for_difficulty_test`、`inconclusive`。依据必须引用具体字段、证据或操作。

- 参考答案错、题面歧义、GO漏条件：修订后重新执行受影响的参考计算与新盲解。
- API/页面合法等价路径很短：保留其作为反例，加强真实问题或淘汰；不为阻止它新增不自然工具禁令。
- 多个答案同样满足：增加自然且有研究动机的选择条件；若只能事后点名赢家，淘汰。
- 环境不稳定：标不可判定，换同生态的稳定切片；不能改记为智能体能力失败。
- 两模型同错、证据却支持别的值：依证据修正，不按多数票决定gold。

建议每候选最多2轮实质修订；这是资源规划值，后续可调整。每轮保留普通编号与理由；不覆盖旧运行，不引入额外hash/冻结contract机制。

## 7. 导出条件

默认按集合目标交付：所有成员先通过内容验证，且预先确定的完整新集合在确认轮中满足[难度判据](02_difficulty.md)，才导出并称为“内容已验证、集合层面更难”的题集。每个成员保留自己的难度结论；单题证据不足时仍可为 `content_validated`，不能因为集合通过就改成 `auto_validated`。后者只用于内容成立且单题相对指定旧对照已确认更难的候选。

若只有内容验证结果，可交付内容候选包，但不能声明难度目标完成；若只有结构分析，状态为 `candidate`。集合未获支持、覆盖不全或仅局部生态可比较时，如实报告范围和未完成部分。未完成人工验证的产物只能声明为自动构建/自动验证，不能在metadata中填造专家人数、耗时或一致率。
