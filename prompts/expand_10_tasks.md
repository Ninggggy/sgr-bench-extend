1. 模型与隔离

构造、参考解、配对、审计和修订使用`gpt-6-astra / high`；普通盲解、捷径攻击、收录复测和旧题对照使用`gpt-5.6-sol / medium`。记录请求参数、实际启动参数、配置和真实会话中的模型/effort，禁止静默换模型或档位。

每次盲解使用全新的实际隔离环境，仅接收一个公开题面、输出规则、统一日期和统一工具。不给答案、作者轨迹、网站画像、其他解答或错误提示，不从构造对话fork。求解者须尽力完整答对；70%目标只留在控制端，不能提示模型故意失败。

2. 先补齐必要执行能力

检查现有工作，使用`construction_pipeline/ten_task_phase/`记录计划、账本、进度和产物。复用运行器，补齐新campaign/ledger传递、非盲阶段解析与资产回收、跨网站工具和可靠恢复，然后继续实际构造，不停在输出计划。已有WQP与Sol实验保留，不重新启动已结束批次。

3. 网站、构造与质量

网站限定在原50题所属12个生态内，优先探索ChemExpo、KEGG、Reptile、WQP、Water Office，并按真实证据调整。争取覆盖4—5个生态，同一构造方法最多计2题。

先验证合法API/批量路径和真实依赖反例，再写题和参考解。每题必须有完整候选范围、唯一可核验答案、源证据、可重算参考程序、关键计算的独立核对，以及CG/GO必要语义对齐。GO可以省略解法，不能遗漏必要条件。

前步证据必须实际改变后续检索、过滤或分支；若固定少量下载已包含全部决策字段，后续仅剩本地计算或过滤，不得把这些计算步骤计为检索依赖。不能通过伪造数据、含糊题面、隐藏条件、禁用合法解法、工具缺失、排序类型陷阱或增加抄表负担制造低分。

4. 开发筛选

每候选先做CG/GO各一次Sol初筛，值得继续才补第二份普通盲解和每题面一次捷径攻击，再由GPT-6审计裁决。两种题面都应有可复查的领域、身份、范围或检索决策错误，且模型取得过实质性进展；只有格式、抄录、数值类型或访问故障不能单独支撑收录。

每候选最多2次实质修订。保留所有版本、成绩、攻击路径与淘汰原因。开发初筛和攻击成绩不混入下面的收录复测。

5. 严格执行低于70%的收录条件

候选定稿且内容审计成立后，先在普通测试计划里登记同一版本的CG、GO各3次普通求解，再启动6个全新、独立于开发的Sol/medium会话。统一工具、预算、评分规则，完成全部预定试次，不因前两次低分提前停止。

以现有确定性评分规则的Item-F1为唯一阈值指标，使用未四舍五入的0—1原始分数：

- CG_mean = (CG第1次Item-F1 + 第2次 + 第3次) / 3。
- GO_mean = (GO第1次Item-F1 + 第2次 + 第3次) / 3。
- 只有CG_mean < 0.70且GO_mean < 0.70，并同时满足质量与实质性错误要求，才允许将这个底题及两个题面收录。

等于70%不收录；任何一组达到或超过70%都不收录。不能用CG/GO合并均值、10题总体均值、最低一次成绩、整题正确率或Row-F1替代。这里要求的是两组各自三次均值，不是声称每一次或未来运行都必然低于70%。

每组必须有3个预定、有效且可评分的数值成绩。存在未解决NA、解析失败、环境故障或缺少试次时，记不可判定、暂不收录；不得补零、删掉失败后缩小分母，或随意追加试次凑出低分。真实基础设施故障仅按运行前写明的有限修复重试规则处理，原记录和成本保留。

把该条件落实到候选收录与JSONL导出的程序检查中，不能只写在报告里。逐题记录6个run_id、实际模型/档位、题目版本、完整分数、两个均值、质量审计与收录结论。阈值比较优先由评分计数计算精确比例，避免浮点误差把恰好70%放行；验证70%边界、任一题面不达标、缺失成绩和混用版本均不能导出。

6. 未达标处理与结果解释

任一题面均值≥70%时，淘汰该版本或在剩余修订次数内实质修改。每个题目/评测协议版本只安排一轮收录复测；不得对未改变的题反复抽样直到低于70%，不得选低分替换高分。新版本重做受影响的开发验证及完整6次收录复测，旧成绩全部保留。

持续补充候选，直到取得10个同时满足上述条件的底题，或触及预算。所有用于决定收录的复测成绩均明确标为筛选成绩，不冒称最终10题的无偏独立评估，也不能据此宣称难于原全部50题或单题已获统计认证。本阶段不另加一轮用于挑题的所谓最终评测。
